# ccqspace.site 上线方案：18093 端口 + 原首页入口

**执行者：DeepSeek Harness（通过用户既有 SSH 别名 `fengz`）**。本交付包尚未修改用户服务器。

## 1. 目标架构

```text
浏览器 -> https://ccqspace.site/（已有首页不变）
                          |
                          +--「代码动画风格工作台」入口
                                     |
                                     v
                  https://ccqspace.site/animation/
                                     |
                      已有 Nginx HTTPS server
                                     |
                      /animation/ 反向代理
                                     |
                           127.0.0.1:18093
                                     |
                  Nginx 独立监听 18093，读取 /srv/motion-atlas/web/
```

公网访问 `http://服务器IP:18093/` 的 HTTP 页面是否可用取决于安全组 / ufw / Nginx 监听地址。**正式向用户推荐 `https://ccqspace.site/animation/`**；这条 HTTPS 连接借助已有 443 证书，不需要在 18093 上单独配置 TLS。

## 2. 执行前审计，禁止覆盖

在本地执行（SSH 别名已配置时）：

```powershell
ssh fengz "hostname; whoami; uname -a; command -v nginx; sudo -n nginx -t; sudo -n ss -lntp | grep -E ':(80|443|18093)\b' || true"
```

然后登录查看实际 Nginx 配置和主站所属目录、首页技术栈，先备份：

```bash
sudo nginx -T > /tmp/nginx-full-before-motion-atlas.txt 2>&1
# 确认配置实际位置后再备份某个配置文件；不要盲目改 /etc/nginx/sites-available/default。
```

注意：执行 `sudo -n` 不可用时，允许通过授权的交互式 sudo 解决，不得向聊天索取或记录密码。`ss` 显示 18093 已占用时先查明是什么项目，绝不能直接停止现有服务。

## 3. 安装静态文件

建议把项目源码放到：`/srv/motion-atlas/`，目录结构保持不变。Nginx 仅公开 `web/`，**不要将 `.dsh/`、`style-library/`、`productions/` 配置成静态网站根目录**。

传输办法可以选择 `scp`、`rsync` 或 Private GitHub 的安全部署流程。Windows 自带 SSH 客户端时，项目根目录附近执行：

```powershell
# 如果服务器上没有目录，需要先 ssh 创建并按服务账号配置权限。
# scp -r 路径写法请按具体目录调整，上传后核对文件完整性。
scp -r .\web fengz:/tmp/motion-atlas-web
```

生产环境可以原子切换目录或先用 `/srv/motion-atlas.next` 准备新版本，再备份旧版并切换。切换前必须确保静帧与 `data.js` 文件存在且可被 Nginx 服务账号读取。

示例 Nginx 配置见：
- `nginx/18093-static-site.example.conf`：18093 独立静态服务。
- `nginx/domain-animation-location.example.conf`：合并至现有 HTTPS 域名 server 的 `location` 片段。

**重要**：这两个是配置参考。DSH 必须通过 `nginx -T` 检查现有 listen/server_name/root/反代结构，再决定使用哪些文件。不能假设主站是纯 HTML，也不能覆盖现有 `location /`。

应用前必须运行：

```bash
sudo nginx -t
# 仅在语法通过时
sudo systemctl reload nginx
curl -fsSI http://127.0.0.1:18093/
curl -fsSI https://ccqspace.site/animation/
```

## 4. 在原首页增加入口

必须检查主站首页代码来源与构建流程，可能是静态 HTML、React/Vue 或其他框架。先定位首页实际文件，再以**最小改动**加入一个项目入口，不改变已有入口与路由顺序。

推荐项目卡片文案：

> **代码动画风格工作台**  
> 探索 341 种视觉风格，查看原始静帧、快速检索提示词，一键生成 DeepSeek Harness 制作任务。  
> [进入工作台](/animation/)

若现有首页是动态聚合项目卡片，应**沿用现有组件与配置规则**新增一项，而非强行插入硬编码 HTML。若首页项目列表由数据库提供，也应按该项目原来的模型字段增加。

确认 `https://ccqspace.site/` 原有项目仍可打开，且新增入口指向 `https://ccqspace.site/animation/`。不要新建一个替代首页，也不要把 `/` 重定向到动画站点。

## 5. 上线验收

- `ss -lntp` 显示 18093 由计划中的 Nginx 监听，无端口冲突。
- `nginx -t` 成功且 reload 后状态 `active`。
- `curl -I http://127.0.0.1:18093/` HTTP 200。
- `curl -I https://ccqspace.site/animation/` HTTP 200（视具体代理缓存和基础 URL，检查完整响应）。
- 主站首页原有项目、登录、其他子路径没有受到影响。
- 打开 `/animation/`，检查 341 种风格、搜索 `O63`、真实静帧、选择→任务导出，浏览器控制台无致命错误。
- 用手机视口检查导航与弹窗是否可操作。
- 检查 `https://ccqspace.site/animation/js/data.js` 和图片请求没有 404。
- 从实际公网浏览器检查 `https://ccqspace.site/` 的入口链接。

**注意**：网页能运行并不意味着 DSH 能在服务器上被调用。此项目设计为纯静态站，不提供公开 Agent 执行 API。

## 6. GitHub Private 验收

DSH 使用本机已授权的 `git`、`gh`；不得把访问令牌保存到仓库或日志。执行后核对：

```bash
gh auth status
gh repo view --json visibility,nameWithOwner,url
git remote -v
git status --short
```

必须看到 **`PRIVATE`**。即使不想公开，源码仍包含原作者版权材料，要保留许可文本和来源归属；不可向外宣称独占拥有全部风格内容。

## 7. 回滚

如果 18093 服务导致异常：撤销新加 Nginx 18093 站点配置和主域名 `/animation/` 两个位置的改动，恢复前述配置备份，并经 `sudo nginx -t` 后 `reload`。若原首页入口有单独代码变更，从对应源码 Git 提交回滚这一条入口即可。**不要回滚或重置主站和其他项目的无关提交。**

保留上线审计报告：现有 nginx conf 路径、修改前后 diff、备份位置、部署源码 SHA、私有仓库 URL、访问检测结果及故障恢复步骤。

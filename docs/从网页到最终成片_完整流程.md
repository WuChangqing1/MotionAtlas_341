# 从打开网页到动画成片：完整制作流程

## 阶段 A：打开风格工作台

**线上部署完成之后**：浏览器打开 `https://ccqspace.site/`，在现有首页点击「代码动画风格工作台」项目入口，进入 `https://ccqspace.site/animation/`。如果 DeepSeek Harness 尚未部署，也可以打开本包 `web/index.html`（本地静态打开）或使用 `python -m http.server 18093 --directory web` 预览。

在左侧按类别筛选。例如：
- `A–G`：字效、粒子、光影代码样片。
- `M`：动态叙事与剪辑方式。
- `K`：卡通、插画、角色画风。
- `Z`：中国传统视觉语言。
- `H`：现成标题/品牌版式。
- `L`：科技产品、讲解、信息叙事。
- `V`：MG 动效工艺。
- `X`：创意编码动画。
- `R`：赛博及参考型风格。
- `O`：电影视觉语言。

界面提供较大字体的搜索框，支持：编号（如 `B3`、`O63`）、名称（如 `水墨`）、关键词（如 `像素`、`发布会`），也搜索每条原始 Markdown 的正文。点击快速标签或「有参考静帧」可进一步筛选。193 张素材是原始静帧，其他风格显示「暂无原始静帧」，占位色块仅为网站装饰，不是生成结果。

## 阶段 B：选风格与检查原文

点击卡片的「查看风格详情」→ 浏览视觉参考 → 查看「原始完整提示词」→ 必要时复制原文。确定喜欢的风格后点「选择这个风格」。可以连续选多个，例如 `B3` 粒子、`L42` 技术发布、`O63` 手绘电影风格，但最终创作时应由分镜安排章节，避免混用互斥语法。

已选 ID 会显示在底部悬浮条；可以「管理已选」，也可以在制作弹窗移除。收藏用于以后复用。两者只保存在本浏览器本地，不会自动同步服务器或 DeepSeek Harness。**注意 M14、M15、M16、M17、M26、M35、M39、M40 这 8 条原文为空，仅作为占位索引，制作前应先补充风格约定。**

## 阶段 C：填写创意和生成制作指令

点击「生成制作指令」，填写：

1. **内容**：最好直接给完整文案、事实点、观众是谁，以及你希望观众最后理解什么。文字越具体，后续分镜越稳定。
2. **时长**：先从 10～30 秒试验，再扩展到 60 秒以上。
3. **画幅**：网页讲解通常 16:9；短视频平台通常 9:16。
4. **声音**：四案试听、仅音效、静音或旁白搭配。原 Skill 的常规流程会先规划四种有区别的音乐方案，未经选择不要假装“已定稿”。
5. **本次阶段**：初次最好选 `card`（只生成分镜任务卡），之后逐渐进入 `still`（静帧）、`audition`（试听）和 `final`（成片）。
6. **补充要求**：颜色、字体可读性、参考图依赖、字幕、是否允许安装依赖等约束。

点击「复制制作指令」或「下载 .md」。复制后，把指令粘贴到已经以项目根目录为工作目录、且具有文件/命令工具权限的 DeepSeek Harness 会话中。**仅复制网页“短描述”不够，DSH 必须读取完整原文。**

## 阶段 D：使用 DeepSeek Harness 制作第一版任务卡

Harness 应做的真实工作：

1. 使用 DSH 的 Skill 加载机制打开 `.dsh/skills/fy-code-animation/SKILL.md`，阅读 `modules/decisions.md` 和本次任务需要的模块。
2. 检查 `<项目根>/style-library/风格提示词/` 是否存在，并执行 `style_library.py build --root` + `doctor.py --root`。
3. 根据你选择的编号定位准确 Markdown；读取全文、核对 SHA，而不是凭风格名称猜。
4. 按原文理解全部内容，找出主要信息、因果关系、转折点和重点词。
5. 确定一条视觉主线和贯穿物件，为每个镜头设计画面变化，写清镜头编号、开始/结束秒数、背景、动作、运动曲线、转场接缝、字幕和声音意图。
6. 输出完整任务卡/分镜表；列出原风格的依赖缺项，标记需要人工决策的事项。

**你来审核任务卡**：动画是不是在表达内容，而不是一屏屏 PPT？镜头有连续性吗？字体、时长、画幅合理吗？确认后可让 DSH 按 Skill 的下一阶段修改任务卡或做静帧。

## 阶段 E：静帧验证

将网页制作弹窗中的「授权阶段」改为 `still`，或者直接让 DSH 「基于已审核任务卡，只输出镜头 S01、S02 的静帧，暂不生成最终视频」。检查：

- 主视觉确实体现所选风格的材质、构图和颜色，而非只套配色。
- 中文不被裁切，重点词可读，字体字号够大。
- 图片或角色是否是可合法使用的素材；无素材则由程序绘制或申请新素材。
- 布局在指定画幅内无溢出；至少包含主要转场前后的代表性静帧。

不合格时先返工风格和静帧，不必马上投入 MP4 渲染。

## 阶段 F：音效与音乐（根据项目是否需要）

选择 `audition`，让 DSH 给出四种有实质差异的音乐和音效设计，并**按授权**用可用的本机音频工具生成试听。如果本机缺相关模型或工具，DSH 应报告缺口，允许选择外部已授权的音频素材或改成静音，不得谎称生成了四段音乐。用户实际试听并选择方案后再定最终音轨。

如果你要静音动画，可以跳过实际音乐生成，但在项目文档里明确「无音乐无音效」。

## 阶段 G：实现代码动画与渲染

切换为 `final`，明确授权。优先要求 DSH 在一个独立的动画作品目录里创建工程（**不要把单条作品源码直接写进工作台的 `web/` 目录**）：

```text
productions/
└─ 2026-示例作品/
   ├─ BRIEF.md                 内容与目标
   ├─ DECISIONS.md             已确认的风格、时长和声音
   ├─ task.json                结构化任务卡
   ├─ shots/                   各镜头源码
   ├─ assets/                  已授权素材
   ├─ renders/                 静帧/成片/预览
   ├─ QA.md                    自检与返修
   └─ README.md                启动与渲染命令
```

使用 Remotion、HTML Canvas、SVG/GSAP 等可重现的动画实现，不要擅自引入大量未经说明的依赖。关键约束：

- 时间轴固定；任意帧可 seek 重现，动画不依赖随机初始状态或当前系统时间。
- 每镜头的对象变化、缓动、转场时长与结构化任务卡一致。
- 中文字幕和字体正确加载、自动断行，不被裁切。
- 声音根据真实音频波形、实际节奏对齐，不能凭空写「已卡点」。
- 有素材依赖清单，版权和字体许可可追踪。
- 导出目标画幅的 MP4/H.264（或用户指定编码）和网页可运行预览。

以 `final` 阶段的实际代码和输出为准，不以聊天中“生成成功”的措辞为准。

## 阶段 H：最终验收与归档

**至少完成**：

- HTML 项目可以本机正常打开/构建；不存在 404、控制台致命错误。
- 检查开头/中段/结尾的随机抽帧，检查分镜衔接与每个重点词。
- 检查导出 MP4 的文件大小非零、分辨率、帧率、音频轨（有声场景）与时长。
- 实际完整播放一次，检查黑屏、跳帧、突变、音画不同步。
- 将运行命令、原始风格 ID/SHA、通过与未通过的测试、人工审片结果分别记录。

作品可由 DSH 在你**另外明确授权**之后提交到你指定的 Private GitHub 项目。网站的公开展示与作品内部资料要分开，不要自动公开未审阅作品或凭据。

## 一个可直接尝试的例子

**主题**：「动作完成，不等于任务成功」，给初学者解释机器人视觉语言模型（VLM）进行任务完成判定的价值。

**选择**：`L42`（暗色科技发布）、`B3`（粒子聚形），先做 `card` 阶段，30 秒、16:9、四案音乐候选。要求用一个贯穿的机械臂与目标物体演示「发出指令 → 实际操作 → 视觉观察 → 判断是否成功」而不是仅展示文字，重点比较真正完成与表面完成的差异。

**操作**：选择两个编号 → 写上述内容 → 生成指令 → 复制给 DSH → 审查 `task.json` 和分镜 → 授权静帧 → 授权正式实现 → 检查 MP4。

## 10. P1FIX3 源码修复（2026-11-07 00:45）

### S06 原来为何是均匀圆环

p1fix2 的分布是：62% 齿顶带 124–144、20% 齿根 100–118、18% 齿侧 112–142；齿根与齿侧覆盖了整个 sector，填满了齿顶之间的角度空隙。粒子虽然多，但角度密度接近连续，所以视觉上合并成圆环；12 个齿帽没有分离。

### 新算法

`timeline.js` 新增纯函数 `ghostGearPoints`（film 通过 `TL.ghostGearPoints` 调用）：

- `step = 2π/12`，齿中心为 `(sector + 0.5) * step`；
- **84%** 点：齿中心 ±0.20step，半径 **130–144**，形成 12 个分离齿帽；
- **10%** 点：齿中心 ±0.275step，半径 100–112，作为齿根；
- **6%** 点：齿侧 ±0.38–0.48step，半径 112–132；
- 齿中心 ±0.25step 之外的谷区只保留少量齿侧/根点，不再用均匀环填满；
- 1800 点、固定 seed、2.2–4.2px、alpha .50–.85。

`drawGhostGear` 虚线 alpha 保持 .42/.55，仅辅助；600 路径保留并增强。

### A/B/C 为何 0/48

`page.evaluate((t, target) => ..., item.frame / FPS, item.target)` 传了 **3 个参数**；Playwright 只接受“函数 + 一个序列化参数”。因此诊断一启动就被拒绝，`particle-diagnostics/` 只有空目录。

### 修复

```js
const result = await page.evaluate(
  ({ t, target }) => window.__particleDiagCapture(t, target),
  { t: item.frame / FPS, target: item.target }
);
```

同时：

- 校验 A/B/C 均为 PNG data URL、1920×1080、帧号一致；
- 记录 48 个文件与 SHA；
- 不再把入场零差异误判为失败；改为每个 target 必须至少有一帧可测差异；
- `manifest.complete` 要求 16 组 + 48 文件 + 无警告；
- 新增 `--tag=p1fix3` 诊断版本目录；
- 新增 `--smoke-particles --tag=p1fix3` 34 帧专项。
